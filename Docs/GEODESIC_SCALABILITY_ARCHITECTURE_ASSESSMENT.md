# Geodesic scalability architecture assessment

## 1. Executive summary

The current geodesic runtime has a credible path to 30,000 organisms at 1×, but the existing frame-driven, serial execution path is unlikely to reach that goal responsively in a busy evolved population. At 30,000, the estimated biology cost alone is about 56 ms per maximum-size substep under the observed mix and a linear extrapolation. Even without presentation, sustaining 1× at that step size permits 33.3 ms per step. Treat 1× as the first engineering target, 10× as a substantial follow-on, and 100× as a throughput research target. A population cap or a responsive camera tells little about achieved simulation speed.

**Recommended architecture:** retain the packed population, the geodesic resource model, and the existing GameObject orchestration. Split position-dependent sampling, numerical movement, and lifecycle arithmetic into explicit kernels. Use persistent native buffers for the fields a proven kernel needs. Retain ordered resource transactions, lifecycle commits, founder scheduling, and RNG ownership. Drive presentation from completed simulation snapshots and give fast-forward a bounded work budget. Selective Jobs/Burst is the first tool to evaluate. A wider hybrid migration should earn its scope with measured end-to-end gains.

- **Start with thermal sampling and physiology.** Lifecycle measured about 102 ms per 100-step frame in the two latest eligible captures. Its marker includes several kinds of work, so the fraction attributable to thermal sampling is still unknown. Compare the same extracted kernel in managed, Burst single-threaded, and Burst parallel forms, including data preparation and completion. Leave the existing ordered lifecycle and reaction code in place for this comparison.
- **Resource contention is already aggregated.** Competition costs scale with request count and occupied node/resource pairs. The serial transactions and clustered workload matter more than the asymptotic cost of the competition pass. No routine all-pairs or population-by-ocean scan appears in the geodesic path.
- **Preserve the geometry and ecology.** Sample vent influence at the organism's continuous position. Keep shared resources and measured stoichiometry, movement boundaries, thermal exposure, birth/death order, and the configured Hydrogen → Fermentation probability of **0.02**. Scene values and source defaults are reference values for scheduling and sizing.
- **Separate throughput from presentation and instrumentation.** The historic allocation regression has an unresolved cause. The local code already gates report-only locomotion work and reduces analyzer formatting allocations. The user has yet to validate these changes. Camera and UI responsiveness are a separate objective from simulated seconds per real second.

This assessment uses the local working tree inspected on 2026-11-23 at `41b7cf7`, with a clean starting status. It covers the authoritative geodesic runtime. The scene references subdivision 6 and a higher-resolution render mesh. The 101,169 active nodes are from the recorded world, so counts can vary with the resolved terrain, sea level and layer settings. Project Unity is 6000.3.29f1 with URP 17.3.0. This report supports performance milestone A7 in the migration roadmap. Solid arrows show data dependencies and the local ordering of each operator. Dashed arrows cross driver or publication boundaries. The environmental drivers are separate Unity `Update` methods. `DefaultExecutionOrder(-1000)` is on the pipeline component, but `RunFrame` is called by the manager, and that attribute does not order the manager's call against the two field Updates. The inspected source does not establish a single chronological biology/resource/thermal ordering across all three. In a synchronous biology batch, agents can read the same committed fields across an environmental deadline. On another boundary, a resource tick can see biology writes made earlier in the same rendered frame. Moving the ticks to exact simulated deadlines or changing batch boundaries can change which state a reaction sees. [Pipeline](../Assets/Scripts/Core/Simulation/ReplicatorSimulationPipeline.cs) · [Manager Update](../Assets/Scripts/Biology/Replicators/ReplicatorManager.cs#L997) · [Surface Update](../Assets/Scripts/Planet/Environment/Temperature/GeodesicSurfaceTemperatureField.cs#L211) · [Resource Update](../Assets/Scripts/Planet/Environment/ResourceSimulation/GeodesicOceanResourceField.cs#L245)

Independent per-agent arithmetic may run in any order on a frozen input epoch. Active sensing, turning and boundary traversal within one agent have longitudinal dependencies. Habitat changes and propulsion spend affect the current reaction/lifecycle. The competition reduction needs a fixed arithmetic order for bitwise parity. The resource commits for a node, reverse lifecycle traversal, count cap, death-carbon additions visible to mutation gates, shared RNG and insertion order constrain state mutation. Separate nodes offer future competition parallelism after grouping and reviewing shared side effects. Within the environment, surface response can run in parallel across cells before publication, and ocean column solves can run independently after surface commit if each worker owns its column. Dissolved/particle fluxes need stable accumulation and a staging barrier. Air–sea exchange couples otherwise unrelated surface nodes through a finite shared atmosphere.

Keep MonoBehaviour and Transform access, render submission, Mesh/material updates, IMGUI, Unity logging and snapshot/publication orchestration on the Unity thread. Jobs can take copied matrices and plain constants. The pure parts of climate, geometry, exposure and stoichiometry need those inputs and disjoint outputs. Moving the current runtime method to a worker would still touch managed arrays, MonoBehaviour methods and callbacks. The serialized owner of a transaction may be a managed stage or a deterministic single writer on native data.

## 4. Complexity and nonlinear risks

Let `N` be live organisms, `A` amoeboid plus flagellar organisms, `P` passive organisms, `C` active ocean nodes, `E` active ocean links, `V` compact outlets, `S` biology substeps per rendered frame, and `Ccap` the rectangular node capacity including inactive slots. `G` is the surface cell count. `U ≤ min(N,C)` is the number of touched nodes per reaction tick, and `K ≤ C` is the abiotic candidate count. `R=7` dissolved channels, the mineral species count, five or six neighbors and the maximum layer count are fixed constants in this source. `Br`, `Bm`, `Tr` and `Tt` denote actual reaction, kinematics, resource and thermal tick counts in the frame.

| Subsystem | Approximate cost | Source-derived limits |
| --- | --- | --- |
| Biology controls, lifecycle and passive schedules | `O(SN + birth/death work)` | Lifecycle is one reverse pass. Active pending-time accumulation and three passive scheduling/position passes touch the population even when kinematics is idle. Birth placement has bounded retries, neighbor tests and an extra thermal sample. On a capacity boundary arrays copy geometrically, giving amortized linear total growth with occasional `O(N)` spikes. Each swap-back copies/clears a fixed set of fields. |
| Continuous movement and sensing | `O(Bm(N + P kp + A ka) + Σ local vent candidates at actual observations)` plus the every-step passes above | `kp/ka` are bounded integration and boundary-search work per moving agent. Neighbors are read from a fixed-width table. Active sensing is countdown driven, caches concentrations/readiness by occupied node within a movement batch, and may also sample vertical targets. It reads the local temporal signal rather than scanning all neighboring habitats. More active agents, coast/depth crossings or longer candidate ranges raise the coefficient. |
| Experienced temperature | `O(SN + Br N + extra observations + Σ q)`, `q` local candidate count per cache miss | Robust coarse-background lookup is constant per query with an ocean epoch stamp. Position-dependent sampling traverses that cell's outlet range. The theoretical dense-overlap worst case is `q=V`. The hot path queries nearby candidates and reuses exact inputs within a biological step. Building the lookup is a world-setup cost proportional to visited outlet footprints with a broad-support worst case `O(VG)`. |
| Biological reactions and competition | `O(Br(N + R U))` plus thermal query work | Several streaming passes, one inventory read per demanded node/resource pair, and at most one ordered reaction commit per supported agent. Generation stamps avoid clearing the complete grid each reaction. There is neither a live all-agent occupancy list nor a sort here. Every producer/consumer on a node is represented by a request, not compared pairwise. |
| Founders and turnover | `O(S + V)` on catalogue/due refresh plus `O(V)` per bounded selection attempt, and `O(B+D)` lifecycle events | Batch founder placement and gradual event scans can spike with outlet count. Ordinary daughter placement and death handling do not visit all organisms or all outlets. `B+D` can be large with similar ages, short lifetimes or a resource shock. Allocations, companion locality, large `ActiveMovement`/growth records and frequent swaps can degrade tail latency. |
| Ocean resources, suspended minerals and abiotic reactions | `O(Tr(V + R(Ccap + E + C) + M(E+C+G) + K + G))` with `M` active mineral species | Vent/air–sea work touches outlets and surface nodes. Clear is capacity-wide. Dissolved apply visits every active node for every channel, including zero delta round trips. Uniform horizontal channels can skip. Suspended mixing has donor and receiver link passes using cached signed flux, then settling; chemistry walks candidates, decays a full cell visual-memory field, and was dense in the sampled world. |
| Thermal fields | `O(Tt(G+C))` approximate, plus `O(Tt E_h I)` with conservative diffusion and `I` diffusion substeps | Surface cells update even with no agents. Approximate profile and conservative column work traverse the participating ocean. The recent response coefficients are already hoisted per tick. The committed ocean version invalidates coarse sampling. |
| Presentation, UI, persistence and diagnostics | `O(N)` each submission/count/HUD pass, `O(N)` per population DTO capture, plus visual-mesh work | Planet tint/recolor touches cells or render vertices on its own schedule. Opt-in diagnostics can add population, candidate/ocean and outlet scans. Analyzer summary sorts frame samples over its reporting window and writes disk output when configured. That sort is over captured frames. |

**Competition and reproduction at scale.** Concentrating 30,000 organisms into one vent habitat reduces `U` and keeps total request/commit work linear, but serializes the busiest node and can increase capacity rejections, precision-limited transactions and branch cost. A more dispersed population costs more cache lines and per-node reads. Fermentation writes H₂ and CO₂ while some other agents consume them. Current factors are resolved from pre-commit demand and inventory, and transactional outcomes then follow the current shared pool order. A different intra-node order can change resource and energy credit. Reproduction has a sequential cap and a shared stream, and a death earlier in the same traversal can change the carbon available for a later mutation gate. The biology can change sharply with density even when the algorithmic cost stays linear. At 10,000 look for scan cost and locality. At 30,000 look for hotspots, birth/death spikes and serial commit span. At 100,000 include peak capacity/resizes, memory bandwidth, worker imbalance and renderer bounds in the budget. [Competition and commit](../Assets/Scripts/Biology/Replicators/GeodesicBiologyRuntime.cs#L618) · [Death recycling](../Assets/Scripts/Biology/Replicators/GeodesicBiologyRuntime.cs#L999) · [Fermentation commit](../Assets/Scripts/Planet/Environment/ResourceSimulation/GeodesicOceanResourceField.cs#L982)

**Repeated work worth removing.** Thermal performance is recomputed for request building, lifecycle and certain sensing calls even when the temperature result is cached. A per-agent physiology result can be reused for identical position, traits, settings and environmental epoch. Movement costs include full-scan locomotion filters, occupancy stamp probes, repeated habitat indexing and per-step world-position writes. The latter feed temperature queries and daughter placement, so changing their cadence requires proving an equivalent local-position calculation. Visual-only life/energy color is evaluated per substep through a callback and written to a companion. Record the input phase that determines the color before moving computation to presentation, particularly for births and divisions. Stats can come from a committed histogram or snapshot. Sample oxygen/OrganicC once per needed habitat and epoch where producer/consumer order permits. Maintain stable locomotion index lists only if filtering is still material after the kernel split. Preserve the current node and arithmetic order when eliminating redundant work. ### Current-path projection to 100,000

Use an illustrative unchanged-architecture model with the captured active mix, thermal footprint and turnover rate held proportional, the same world and configured maximum step of 1/30 s, and a full visible-population submission path. For `n=N/1000` and `s=1,10,100`, the modelled CPU scopes in ms/frame are `T(s,n)=(s/100)(55+186n)+1.05n`. The 55 is environment plus abiotic chemistry averaged across due ticks. The 186 is rounded from lifecycle, reactions and active/passive movement. The 1.05 is measured agent render CPU at 1,000. The resulting conditional throughput is `min(s, (1000s/30)/T)`. It assumes modelled CPU work dominates wall time and omits overhead outside the selected scopes. Environment costs are bursty and ticked separately, so the average is a weak latency predictor, especially at 1×. At frame deltas below the clamp, the current scheduler uses a smaller step. The formula is a clamped-load stress projection, with the target speed as ceiling. It is not an extrapolation of a measured 1× or 10× run.

| 10,000 | 30 ms / 1× | 202 ms / 1.65× | 1.93 s / 1.73× |

At 1,000/100×, actual historical frame time exceeded the marker model by ~33–58 ms. At 10,000/1× there is roughly 4 ms of modelled headroom at the clamp. At 30,000/1× the model already exceeds it before omitted work, so responsiveness and throughput both need attention. At 100,000 this is a capacity-planning slope. Current scene/ startup caps vary and must be recorded explicitly if larger populations are later tested. At 30,000, the expected simulation-only cost is ~56.35 ms per 1/30 s step. Its per-step budgets for 1×, 10× and 100× are 33.33, 3.33 and 0.333 ms, before presentation. This implies at least ~1.7×, ~17× and ~169× improvements to the modelled simulation cost at those targets. Even the observed environment average alone implies ~0.55 ms per step at the current integrator, so biology-only speedups cannot deliver 100× under that historical environment cost. Amdahl's law also constrains the first experiment: halving the whole 102 ms lifecycle scope could save at most ~51 ms in a ~290 ms reference frame with other work held fixed. The sampling/physiology kernel is a subset of that scope.

## 6. Architecture options and kernel boundaries

| Current methods | Candidate numerical work | State boundary and caveats |
| --- | --- | --- |
| `GetBiologicalTemperature`, `CalculateTemperaturePerformance`, `AdvanceExposure`, `RunLifecycle` | First extract post-movement temperature and performance. Then add per-index exposure, age and basal/stress maintenance arithmetic with post-reaction energy inputs. The same frozen post-movement temperature/performance can feed `BuildRequest` on reaction ticks. | Snapshot geometry, thermal version, settings and habitat. Fill the per-index outputs once. Fold counters in original order if required. Apply physiology in the reverse lifecycle stage before death and reproduction. Do not pre-decide cap eligibility or use pre-reaction energy. Preserve exposure cause precedence and exact float addition order. |
| `SampleOccupiedHabitats`, `BuildRequest`, `AggregateDemands`, `ResolveAvailabilityFactors`, `CommitRequests` | Freeze node inputs with stable touched-node discovery. Independent requests and post-factor extent math can be batched. Availability factors can be per touched node after ordered demand reduction. | Preserve the request index, node traversal/order and measured resource writeback. Start with `BuildRequest` computation and its derived physiology inputs. Continue ordered demand, resource and counter commits. If profiling warrants, group by node with stable intra-node indexing, then merge shared flags/diagnostics in a defined order. |
| `RunGeodesicMovement` and `RunActiveMovement` | Integrate passive agents from flat topology. Keep the existing SoA and consolidate work proven redundant by dataflow. Snapshot unchanged controls by value at the frame/work-batch boundary with explicit invalidation on setting changes. ## 7. Timestep and responsive fast-forward

The current step count multiplies work on the Unity thread. At a 1/30 s clamp and 100 steps, each completed frame contributes about 3.33 simulated seconds. A 300 ms frame therefore gives ~11.1× and roughly 3.3 FPS. An expensive frame still executes the configured steps. The biology clock slows when the clamp is hit, while the environment has separate, retained cursor backlogs and tick guards. This is a scheduling limit on responsiveness and couples the physics trajectory to frame partitioning. It also exposes a throughput limit from the quantity of work per simulated second. Changing where steps run cannot resolve that quantity on its own.

| Alternative | Effect on model and presentation |
| --- | --- |
| Budget whole committed batches and present a snapshot | A scheduler can yield at substep or operator boundaries and submit the last complete snapshot every frame. Exact replay is possible with the same input events, step deltas, environment visibility/commit boundaries and ordering carried across the new presentation frames. Simply shortening the current `for` loop leaves resource/thermal Updates tied to rendered frames and changes their interaction with biology. For a parity implementation, carry logical batch boundaries explicitly, with presentation decoupled. Report the time of the committed snapshot, achieved speed and any lag against the requested clock. |
| Fixed-step accumulator independent of rendering | Use a named step policy with bounded work per rendered frame, ordered timestamps and a clear rule for overload. Wall-time target can accrue bounded debt or slow on sustained overload, while committed simulation time advances by completed work. Avoid an unbounded catch-up spiral. Moving from today's variable frame delta to a fixed step is a numerical and behavior change during unclamped play. A fixed 1/30 s sequence is comparable to a previously clamped sequence only if environmental and control events match. At lower FPS, a single step or whole environment operator that exceeds the budget still stalls. Resumable numeric chunks or worker stages with deferred publication address that case. |
| Chronological multirate events | Biology already uses 0.10 s movement and 0.25 s reactions. Resources and temperature already use their own longer intervals. Keep cadence values first and define which temperature/resource versions a coincident biology step sees. A later migration can advance each due operator at its exact timestamp and define a single tie order. That changes the existing frame-batch operator split. Establish convergence and ecological consequences before adopting it. Budget by due work and use an atomic commit so UI cannot read half a transport tick. |
| Per-agent scheduling for infrequent events | Wander refresh, passive vertical trials and founder emergence have existing deadlines. Due lists can save visits if they apply the same step-boundary events with the same deterministic ties, bounded retries, processing order and child initialization. Moving reproduction or mortality to predicted times is harder. The present probability is `Clamp01(rate * dt * performance)` after age, maintenance and eligibility, with state-dependent RNG consumption and a cap. It is a discrete trial policy. Exponential survival/event timing implies a different hazard, branch order and genealogy. |
| Analytical integration and larger subsystem steps | A constant exposure/maintenance segment may admit an exact mathematical update split at input changes, clamps and threshold crossings. Repeated float writes, damage recovery, energy availability, reproduction draws and death timing can still differ. Movement has continuous coast/vertical constraints and bounded integration; transport has explicit mixing/settling stability, shared resources and source/chemistry splitting. Choose any new interval per operator from temporal error, observed ecology and conservation, and leave those changes outside the first speed experiment. |

For responsive fast-forward, treat camera input, GUI and draw submission as real-time work. Consume the latest complete snapshot while an independent stage runs or between complete work slices. Pause, speed changes, world replacement and any future save must rendezvous at a committed epoch. A pending acceleration backlog should show lower achieved throughput in the UI. Snapshot age and display cadence can improve even if wall-clock time to advance a fixed simulated interval stays the same. Avoid scheduling rapidly and blocking on a worker fence each frame. Use measured worst-case operator latency when choosing batch sizes. ## 11. Recommended architecture and direct answers

1. **Can the architecture support 30,000?** The packed data and sparse shared-resource algorithm can scale to this size. The existing serial frame path offers little margin for responsive 30,000/1× in the observed ecology and falls well short of 10× and 100× under the model.
2. **Is ECS justified?** The current source already supplies packed hot state, one world owner and instanced rendering. ECS would add migration across the most order-sensitive systems before proving a missing capability.
3. **Does selective Burst/Jobs offer better value?** Yes. A small thermal/physiology pilot can quantify gains and their main cost, array staging and synchronization, before moving ownership.
4. **What should migrate first?** Post-movement organism thermal sampling and performance, then pure maintenance/exposure and request arithmetic. Port batched movement against immutable geometry once scheduling and data ownership are demonstrated. Promote environmental kernels when the measured environment floor warrants it.
5. **What should stay ordered?** Demand reduction if exact parity is required, measured resource commits, lifecycle admissions/removals, cap, mutation and RNG, founder placement, and coupled atmosphere/chemistry merges. Keep Unity-facing operations on the main thread. At scale, their arithmetic and preparation can still use frozen inputs and disjoint outputs.
6. **Does the timestep limit performance?** Yes. It packages a full biology batch into one frame, mixes variable biology steps with separate environment cursors, and slows when clamped. A scheduler can greatly improve responsiveness. Reducing actual work per simulated second is required for higher throughput.
7. **What is realistic?** 30,000/1× is a reasonable engineering milestone for a measured hybrid path. 10× needs a large reduction in per-step work and may need accepted integration changes after a reference is established. 100× is aspirational across biology and environment. Render-speed improvements alone do not establish these milestones.
8. **What can change correctness?** Sampling phase and continuous position, layer transitions, inventory/energy credit, finite-precision ordering, exposure/reproduction thresholds, births/deaths and RNG draw count, and incomplete timestep/state restoration are the main risks.

The smallest useful milestone is **one post-movement thermal/physiology read-only kernel feeding the existing managed path through a reversible switch**. It isolates compilation gain from multicore gain without confounding a timestep, resource scheme or renderer rewrite. If per-agent staging dominates, measure native authority for the selected hot columns before expanding to movement. If the thermal portion is small in the controlled reference, the next candidate is the larger measured independent arithmetic inside lifecycle or movement. Preserve the baseline all the way through this decision.

## 13. Open questions and required future measurements

- **Lifecycle attribution.** Split temperature sampling, phenotype/thermal response, maintenance/exposure, presentation color/timers, births and deaths. Compare stationary/coarse, vent-dense, active-heavy and high-turnover cases.
- **Current allocation and observer costs.** Obtain allocation call stacks separately from clean timing, and compare reports off, analyzer off, CSV off and CSV on with identical ecology and frame configuration. Record GC and tails by capacity/turnover, and isolate engine/editor waits and visual work absent from the markers.
- **Contention and bandwidth.** Record unique touched nodes, median/upper occupancy, the busiest node's serial commit span, retry and precision rejection counts, job imbalance, geometric cache footprint, and measured staging/allocation peak.
- **Scheduler evidence.** Record actual callback/commit order, environment version seen by each sample, frame-batch-dependent trajectories, and p95/p99 CPU/GPU/input delay with rendered snapshots. Compare throughput against matched simulated age and note scheduled work actually executed. Define how overload, pause and user commands affect logical event ordering before replacing the scheduler.
- **Rendering and world control.** Record resolved population caps, visible instance count, body mix, mesh/material and bounds, tint refresh frequency, and platform GPU budget. Separate camera/UI latency and presentation FPS from biology throughput and document reproduction/growth visual acceptance.

Agree ledgers and tolerances for sources, sinks, reaction products, energy, exposure and birth/death across two accepted execution policies if moving beyond parity.
