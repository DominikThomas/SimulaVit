# Geodesic P0 manual benchmarks

These reference configurations are for user-run measurements on the merged B2 performance branch. Population targets and observation windows are proposed from source. [Performance roadmap and branch point](GEODESIC_PERFORMANCE_ROADMAP.md)

## Keep benchmark settings separate

1. Keep a copy of the ordinary saved startup JSON. On Windows the default is `%USERPROFILE%\AppData\LocalLow\DominikThomas\SimulaVit\startup_config.json`. In Unity Play Mode on `PlanetScene`, find the **Simulation Startup** object. Before editing setup, disable **Save Startup Config On Start**. This also disables automatic draft saves on Back and quit.
2. For a first reference run, use **Reset Defaults** and **Advanced → Reset Advanced to Defaults** within that protected Play Mode session, then apply the common settings and case overrides below. Reset the two groups before entering benchmark values. Use the checked-in scene controls for unlisted fields. For repeats, the controller can save and load a benchmark JSON via its Inspector context menu. Set **Saved Config File Name** to a distinct name such as `p0_A_1000.json` before choosing **Save Current Startup Config**. Keep each case’s benchmark JSON with the results. The detailed profiling toggle is session-only and must be recorded separately.
3. Keep these Inspector edits in Play Mode. Start each repeat from **New Game**, or load the named benchmark setup JSON into the setup screen and generate a fresh world. Geodesic world continuation is unavailable. Returning to the main menu flushes the performance CSV. [Startup controls](StartupSetupTabs.md#performance-recording) · [Existing recording and CSV behavior](GeodesicPerformanceBaseline.md#csv-output-location)

## Four cases

`N` is the target live population. The startup UI limits each founder request to **10,000**. Lower measured population bands are valid results if growth or placement falls short.

| Case | Availability and settings | Founder requests and measurement qualification |
| --- | --- | --- |
| **A · Passive hydrogenotrophs** | Hydrogenotrophy and Passive drift only. Keep the common rates and division settings. Maximum population `N`. | Vent founders `min(N, 10,000)`, other counts `0`. Use post-batch steady windows with hydrogenotrophic and passive fractions near 100%. |
| **B · Passive photosynthesis** | Oxygenic photosynthesis and Passive drift only. Maximum population `N`. Keep scene full-light CO₂ demand **0.02** and energy per CO₂ **4**. | Vent founders `0`, photosynthetic founders `min(N, 10,000)`, other counts `0`. Verify the photic cohort was placed. Use matched daylight windows and label any night windows separately. |
| **C · Active chemotaxis** | Hydrogenotrophy only. Enable Passive drift, Amoeboid and Flagellar. In **Debug** enable geodesic chemotactic steering. Use locomotion mutation and upgrade probabilities **1**, anchoring probability **0**, anchored release off, Inspector mutation override off, initial biomass target **0.05**, and maximum population `N`. Retain scene movement speeds, sensing intervals, and propulsion costs. | Vent founders `ceil(N/4)`, other counts `0`. Founders begin passive. Allow births to establish the normal Passive → Amoeboid → Flagellar path. Start timing when combined Amoeboid/Flagellar share is at least **60%** and `active_senses` and `active_integration_steps` are positive. Report lower-active windows with their actual share. |
| **D · Mixed ecosystem** | Enable all eight metabolisms and all four locomotions. Use the scene’s ordinary mutation settings with Hydrogen → Fermentation **0.02**, chemotactic steering on, locomotion override off, initial ocean O₂ **0.02**, CH₄ **0.005**, Fe²⁺ **0.02**, vent rates **10/1/0/0** in common order, and maximum population `ceil(1.1 × N)`. Keep predation enabled, candidate budget **24**, probability **1**, range **0.25 planet units**, cooldown **1 sim s**, predation diagnostics off. | Vent founders `min(floor(0.7N), 10,000)`, photosynthetic founders `floor(0.05N)`, and `floor(N/50)` for each experimental Saprotroph, Methanogen, Methanotroph, and Predator batch. Those four routes depend on local eligibility and capacity. Select a window with at least two metabolisms at **5%** or more apiece and record the whole mix. For predation attribution use positive `predation_searches` and report candidates, attempts, and successful captures. |

A and C use extra vent H₂ to help establish their controlled cohorts. C uses accelerated locomotion acquisition and is a movement workload. Use D for ordinary mixed competition and turnover. At 30,000, let the population grow into the target band with the same case settings. Report a smaller measured band or skip the high-population case if it falls short.

## Capture matrix and comparable windows

| Target live organisms | Requested speeds | Initial priority |
| --- | --- | --- |
| **1,000** | **1×, 10×, 100×** | A–D at 1× first. Use A or B and D for the higher-speed rows as practical. |
| **10,000** | **1×, 10×** | A and D at 1×, plus C if active cost is competitive. Choose one established workload for 10×. |
| **30,000** | **1×** if practical | One D window at 1× is enough to establish the first scaling point. Record the closest achieved population range if lower. |

1. Start paused, confirm the effective profile, and choose a speed from the runtime selector. Use the same startup/warmup speed in each repeat. For an evolved case, grow up to the target band, then switch once to the requested measurement speed at a recorded simulated age. Exclude mixed-speed rows, startup, founding, and warmup. Read the interval from `end_simulated_seconds - simulated_seconds` through `end_simulated_seconds`.
2. Start with a 5–10 real-second summary interval. Aim for at least three full windows and roughly 60 real seconds per comparable run, with enough completed frames for a meaningful p95. At very low FPS use longer reporting intervals or report the limited frame count. Repeat the core comparisons three times and keep the individual results. If the ecosystem moves out of band, select a shorter comparable interval and report its length and sample limits.
3. Use windows within **±10% of N** for a named target. For a paired comparison, aim for means within **5%** of one another and comparable dominant metabolism and active/passive shares within **5 percentage points**. Match simulated age, light regime, vent locality where relevant, birth/death intensity, and the ecology’s growth stage. Record a steady population and a turnover burst separately. Compare the number of due environment ticks and simulated seconds advanced per step, since real-time frame pacing can change the step sequence and operator workload even with the same seed.
4. Save the raw CSV and benchmark JSON with the case, case overrides, startup and measurement speeds, simulated interval, repetition number, camera/build/hardware conditions, and toggles. Include population and all metabolism and locomotion shares, births/deaths, movement and predation work, active nodes, environment tick counts or backlog when available, GC, FPS/frame time, and relevant markers. Record unattained targets and absent pathways as observed.

Use `sum(simulated_seconds) / sum(real_seconds)` for actual throughput and `sum(frames) / sum(real_seconds)` for FPS across selected windows. Aggregate CPU ms per step by dividing the sum of covered stage milliseconds by the sum of actual steps. For `_avg_ms` columns, multiply by frame count before summing. Report per-window p95 ranges or compute a pooled p95 from frame-level timings. `simulation_cpu_ms_per_step` includes the existing biology/pipeline, resource Update and surface-temperature Update roots, averaged over biology steps. Main-thread frame timing also contains engine work and waits.

## Profiling modes and overhead

- **Baseline.** In **Advanced → Performance recording**, enable recording, CSV and timestamped names. Keep **Detailed Geodesic profiling (this session)** and periodic Console summaries off. Set **Chemistry telemetry interval** to **0** and leave biology logging/accounting, movement diagnostics, per-organism taxis, and explicit predation diagnostics off. The analyzer still records ordinary chemistry tick and work counters. Chemistry telemetry controls reporting.
- **Attribution.** In a matched fresh run, enable **Detailed Geodesic profiling (this session)** in the same Advanced section. Keep CSV, interval, and all other observers identical to baseline. Only enable chemistry telemetry or biological ledgers in a separate diagnostic capture when investigating state or conservation. Record their settings and exclude their overhead from baseline comparisons.
- **Overhead.** Repeat a representative passive case and a mixed or active case with recording disabled, then basic recording with CSV and Console off, then basic CSV, then detailed CSV. Set the same interval in recorded runs. If using the Unity Profiler, keep its connection and options the same everywhere. For recorder-off runs use real elapsed time and the pipeline’s **Simulation Time Seconds** or the speed display’s actual-speed reading. Compare frame time, throughput and GC with basic recording, and report the detailed-minus-basic delta as ms/frame and percent. Read the sample counts and report any difference inside baseline repeatability as unresolved.

Expected overhead comes from optional timing scopes, extra recorder reads/resets and wider formatted summaries and CSV rows. Fine timings touch one of 64 packed-slot residues per step, chosen deterministically from the step ordinal. Founder scopes use existing call boundaries. Predation counts search outcomes already available in the loop, independently of the biochemical ledger. Off mode makes no additional detailed timing calls or recorder reads. It still encounters lightweight slot checks and scope guards. The observer adds no population scan and no per-organism allocations. The prior passive inner-loop markers are consolidated into the sampled integration and per-mode mapping scopes. Their removal makes comparison with an older instrumentation revision a separate observer comparison. Overhead is unmeasured.

## Reading attribution

Detailed timings are appended to the existing CSV columns. Both recording modes use the same header. Startup opens a new CSV per capture, and a standalone capture targeting an older header creates a separate file. Each stage has a timing and a `_samples` column counting marker invocations. `detailed_slot_stride` is **0** for basic recording and **64** for detailed recording. Exact `_avg_ms` values sum observed invocations and divide by completed rendered frames. `_estimated_avg_ms` values scale the sampled timings by 64 before dividing by frames. Fine markers in the Unity timeline show the observed calls. Short windows, small groups, and clustered turnover yield noisy estimates. A sampled timing with zero hits is `n/a`, even if the corresponding stage ran. Exact registered stages with zero calls read zero. Use sample counts and longer matched windows when an estimate matters.

| Area | Timing boundaries and overlaps |
| --- | --- |
| Lifecycle | `LifecycleReproduction` is the inclusive existing lifecycle pass. `Lifecycle.TemperatureAndVents` samples the experienced-temperature lookup, including cache activity. `Lifecycle.ThermalExposureAndEligibility` covers performance arithmetic and exposure/eligibility writes. `Maintenance` covers the energy debit. `GrowthAndReproductionEligibility` covers carbon/energy/cap gates and the ordered reproduction roll. `ReproductionAndMutation` includes construction, inheritance, placement, credit/split, and newborn initialization. `DaughterPlacement` is a child of that timing. `DeathRecyclingAndCompaction` includes recycling and ordered removal, or removal alone for captured prey. Age, visual/color work, death classification, and housekeeping can remain in the lifecycle residual. |
| Founders | `FounderLifecycle` covers normal deferred and gradual work after the biology step. `FounderLifecycle.Experimental` covers due or pending methanogen, methanotroph, saprotroph and predator work at their existing step boundaries. It is disjoint from the normal founder/lifecycle aggregate. Immediate vent and photosynthetic startup batches occur before performance windows. |
| Passive movement | `PassiveMovement.KinematicsAndBoundary` includes the sampled `Integration` and `SpatialMapping` scopes. `VerticalEvents` covers scheduled layer changes. `VisualTarget` includes layer-center radius mapping and world-position refresh, which lifecycle also reads. Passive drift uses geometric ocean-node and layer data. Temperature, light, and chemical sensing are attributed at their other call sites. `Movement − ActiveMovement` also includes shared pending-time and population counting. |
| Active movement | `ActiveMovement.Sensing` and `ActiveMovement.Vertical` are existing exact children of the active pass. Sensing includes the countdown check, with actual observations identified by the work counters. Vertical includes its own habitat observations and depth work. The sampled `Integration` covers horizontal steering, propulsion/energy, and travel. `SpatialMapping` covers active habitat checks and boundary traversal. Active world-pose writeback and setup remain in the parent. |
| Dissolved reactions | `ReactionEvaluation.HabitatSampling` and `RequestBuild` cover request preparation. `DemandAggregation`, `AvailabilityResolution`, and `CompetitionResolution` are disjoint competition stages inside `ReactionEvaluation`. The historical `AgentEnergyAndStores` label covers the whole per-agent commit loop, including measured transactions. Sampled `Commit.<metabolism>` columns split that loop by strategy. `MeasuredTransaction` is their nested resource-field work, including attempted/rejected transfers. `ReactionCommit` is the existing staged-delta pass, separate from those per-agent transactions. Predator queuing still appears under `RequestBuild`. |
| Predation | `Predation.Capture` covers the whole predation pass after dissolved reactions. It contains exact `IndexBuild` and sampled `CandidateSearch` and `CaptureResolution`. The search timing covers each sampled search, including all candidates it examines. Resolution covers the ordered attempt, transfer, and bookkeeping once prey is found. `predation_searches`, `predation_candidates_examined`, `predation_capture_attempts`, and `predation_captures` are window totals. Captured prey removal is measured in lifecycle. |

Compare a parent with its children or subtract children when the sampling supports it. Add only disjoint scopes. `biology_reactions_including_competition` keeps its dissolved-reaction scope, and `biology_lifecycle_and_founders` retains lifecycle plus normal deferred/gradual founders. Both predation and experimental founders already contribute to the inclusive simulation root. In very fine scopes the timing calls themselves can be a material share of the estimate.

For the P1 decision, calculate lifecycle temperature and exposure cost per step and as a share of lifecycle in A and D. Compare that with maintenance, growth gates, placement and recycling, and with the stronger movement case in B or C. Use the basic captures to rank parent costs and quantify the detail pass’s observer effect. Keep result rows by profile, revision, population band, requested speed, simulated interval, and repetitions so changes and discarded attempts remain auditable.
