# Geodesic migration roadmap

**Authority:** the single current roadmap for migration status, priorities and next steps. Reviewed **2026-11-20** against local source at `f0b4b01`, starting from a clean working tree. Concurrent local profiling edits appeared during the audit and were preserved; their presence does not establish performance acceptance. This audit ran no Unity, builds, tests, simulations or benchmarks. Historical results cited below were recorded by earlier work and were not reproduced.

The [implementation plan](GEODESIC_PLANET_IMPLEMENTATION_PLAN.md) retains architectural contracts and development history; its phase lists and embedded next-task prompts are historical. The [documentation inventory and audit](README.md) explains document roles and unresolved evidence. Update this roadmap when a milestone changes; keep detailed implementation and experiment evidence in its subsystem report.

## Objectives and boundaries

Replace the **LegacyCubeSphere simulation topology and runtime** with a stable **GeodesicIcosphere** world: independent simulation/render resolutions, physical layered inventories, eight reachable metabolisms, coherent organism lifecycle, equivalent essential presentation, reliable persistence and measured performance. Preserve configured user values, including Hydrogen → Fermentation **0.02**. Source initializers and historical experiment configurations are not authority to reset saved settings.

Migration parity permits deliberate corrections: conservative carbon/energy transfers, local habitat gates and consistent temperature physiology are preferable to reproducing legacy defects. Record each behavioral difference and its acceptance evidence. Expanded nutrient ecology, spatial weather and alternative-world ecosystems are separate post-migration work, not prerequisites for merging a functioning replacement.

### Status and priority vocabulary

| Status | Meaning |
| --- | --- |
| Operational, bounded evidence | Reachable production path with recorded execution evidence at a stated checkpoint; not proof of current whole-world stability. |
| Implemented; validation pending | Wired production behavior, without acceptance evidence for the latest implementation. |
| Partial | Some required components are implemented; the complete feature is absent. |
| Unreachable reaction code | An injected organism can enter a reaction branch, but normal founders/evolution cannot produce the strategy. This is not gameplay parity. |
| Legacy-only / absent | Available only in legacy mode, or no geodesic implementation found. |
| Deferred / proposed | Deliberately outside migration or a future design without a complete implementation. |

**P0:** stabilize or resolve correctness blockers. **P1:** required parity/v1 work. **P2:** optional visual refinement. **P3:** post-migration development. Priorities express ordering, not estimated effort or dates. A milestone is complete only when its acceptance criteria have recorded results; code or a test file alone is insufficient.

## Legacy retirement and technical debt

- Keep the legacy implementation available until the replacement is complete and validated. Legacy-only `PlanetResourceMap` APIs and metabolism/steering/predation systems are reference and compatibility code, not automatically dead code.
- Audit dependencies by runtime grid and callers, not filenames. `Planet/Geodesic/Rendering/IcosphereRenderGeometry`, `IcosphereRenderMeshBuilder` and `IcosphereDirectionMapping*` are legitimate new geodesic rendering infrastructure and must remain.
- Keep generated-world cache reuse separate from complete simulation persistence. Cache hits must preserve physical masks, TIN/lake/delivery authority and invalidation behavior; they cannot restore organisms, chemistry, weather or founder RNG state.
- Risks include piecewise coarse thermal backgrounds, deliberately large/anisotropic vent niches, local food/thermal mismatch, zero-signal taxis blindness, selection favoring cheap anchored lineages, float transfer precision, inactive reaction accounting, expensive offscreen VFX and unresolved high-speed bottlenecks. A1–A7/C1 address these before promising stable ecology.
- `ReplicatorPopulationState` owns geodesic cell, lifespan and biomass target as well as other hot fields. Companion objects remain at construction/debug/trait boundaries. Broad copying or wholesale AoS-to-SoA rewrites need evidence; they are not automatic migration requirements.
- Old hydrology investigations retain rejected experiments and useful measurements. Do not reintroduce retired major-outlet logic or revive an old cache proposal merely because it appears as a next step in a historical document.
