# Geodesic terrain and hydrology caching investigation

9 November 2026 · Persistent snapshot proposal for review · Source inspected at `97cec50`

**Recommend option B, a persistent completed-planet snapshot with authoritative hydrology.** It serves the repeat-development workflow across game and Unity restarts. Restore physical terrain and ocean classification, the exact post-carving surface, final TIN, all-lakes routing, verified sediment corridors and shoreline connections, and final delivery/destination data. Rebuild visible lakes, sediment terrain, crossings and ribbons from that authority, then initialize each game's dynamic systems normally.

Use a persistent post-carving terrain checkpoint as the first integration step toward B. Keep finished mesh buffers optional. The archived reference spent **24.65 s in TIN accumulation and all-lakes routing alone**. Its existing presentation-only rebuild took **2.12–3.13 s**. These are measurements of existing paths and establish where each snapshot option can save work.

The proposal uses source inspection and existing native captures. Only this report is being revised.

## 2. Actual generation order and data ownership

1. **Simulation and physical ocean.** `GenerateGeodesicPrototypeStages` validates the simulation topology, builds transport and samples cell terrain. Classification computes oceanic relief/raw radii, resolves sea level and computes initial below-sea membership, coastline, shore distances and bathymetry. It preserves the bathymetry mask, then classifies retained/excluded seas and adjusts water/coast fields. Inland uplift uses retained-coast distances. Exclusion can leave baseline bathymetry fixed while changing membership, uplift and infill. [Generation](../Assets/Scripts/Planet/Common/Generation/PlanetGenerator.cs#L803) · [Ocean classification](../Assets/Scripts/Planet/Common/Generation/PlanetGenerator.cs#L2054)
2. **Displacement and geological infill.** Render topology/mapping drive a fresh mesh, displacing by terrain samples, mapped bathymetry and inland uplift. When infill is enabled and seas were excluded, this happens before ocean-layer/resource/temperature initialization so those systems can query the infilled terrain. Infill changes XYZ, surface radii and height/normalization arrays, records edited vertices/facets and keeps the pre-infill retained render mask. Otherwise the base render surface is built after those fields. Colour, normals, bounds, anchors and mesh assignment precede hydrology. Ocean facets are prepared here for both shoreline fitting and rendering. [Infill and surface writes](../Assets/Scripts/Planet/Common/Generation/PlanetGenerator.cs#L1527) · [Ocean geometry](../Assets/Scripts/Planet/Common/Generation/PlanetGenerator.cs#L2647)
3. **Initial TIN and ordinary carving.** `BuildAdaptive` uses render triangles, current XYZ, selected height input and an ocean mask from infill or initial render mapping. It builds adjacency, facet gradients and flat routing, traces independent runoff parcels, accumulates discharge and extracts raw networks. Carving requires a fresh surface, the enable switch, `Visible` mode and configured filter exactly zero. Intermediate basins are built with lake qualification deferred. Each pass plans from raw basins and networks with null lake geometry/routing. Cuts update the mesh, five paired arrays, queries and anchors. Even a zero-cut pass rebuilds TIN with the initial frozen mask. Intermediate builds require a sea-sphere crossing. The final build uses final mode. P passes mean P+1 TIN builds plus possible temporary coastal proofs. [Carve loop and TIN setup](../Assets/Scripts/Planet/Geodesic/Hydrology/GeodesicRiverSystem.cs#L294) · [TIN builder](../Assets/Scripts/Planet/Geodesic/Hydrology/GeodesicTinHydrology.cs#L1006)
4. **All-lakes routing.** The final TIN also supplies channel anchors and triangle-to-cell mappings. The visual entry re-extracts raw networks and can capture rejected paths. `EnsureRoutingLakeGeometry` uses area and depth of zero, with the existing structural eligibility and nested/submerged suppression. With lake integration enabled, exact entries clip reaches, witnessed spills/joins define lake edges, and parcel replay records first-lake membership and raw-channel contributors. The lake DAG resolves unique discharge with conservation checks. The facet receiver is a summary, and the original parcel trajectories carry more information. [Final build and routing entry](../Assets/Scripts/Planet/Geodesic/Hydrology/GeodesicRiverSystem.cs#L647) · [Lake routing and parcel replay](../Assets/Scripts/Planet/Geodesic/Hydrology/GeodesicTinLakeRouting.cs#L181)
5. **Verified connections and authoritative delivery.** `ResolveSedimentCorridors` analyzes all-lakes baseline delivery using retained-ocean component labels. It selects eligible closed catchments, protects all-lakes footprints, then chooses primary connections and supplemental routes to secondary receivers or exact exposed shoreline handoffs. Some record sparse elevation edits. Shore-only handoffs can retain a fitted path with zero edits. A second analysis verifies cycles, parcel membership and conservation. Failed verification discards links and edits and uses baseline delivery. Final authority is the original final TIN plus lake edges and verified corridor overlays. Its receivers and heights remain pre-sediment. [Orchestration](../Assets/Scripts/Planet/Geodesic/Hydrology/GeodesicSedimentCorridorRuntime.cs#L10) · [Planner](../Assets/Scripts/Planet/Geodesic/Hydrology/GeodesicTinSedimentCorridors.cs) · [Delivery](../Assets/Scripts/Planet/Geodesic/Hydrology/GeodesicDrainageDelivery.cs#L194)
6. **Visible lakes and sediment surface.** `WithVisibility` requalifies the raw basin descriptors. Retained lake surfaces are clipped, then the renderer applies corridor edits over the source mesh and replaces eligible filtered wet footprints with level beds, dry facets and rim walls. The replacement mesh serves rendering and collision. Generator surface queries/anchors remain on the base infilled/carved terrain. River draping can use the corridor query helper and exact lakebed seam levels. [Surface composition and lake refresh](../Assets/Scripts/Planet/Geodesic/Hydrology/GeodesicRiverSystem.cs#L1141) · [Sediment mesh](../Assets/Scripts/Planet/Geodesic/Hydrology/GeodesicTinLakeSediment.cs#L45)
7. **River geometry and completion.** Validate, interpolate and project ordinary paths with current fallbacks. Accepted inlets drive former-lake crossing paths over the bed mesh, with outlet visibility sometimes extended below its usual cutoff. Crossings emit river geometry. Lake outlets and corridors also emit geometry with accumulated/unique-flow widths, joins and tapered shoreline caps. The renderer records mouths, fitted contacts, audit evidence and colour spans. Destination colours read final delivery. Without lake routing or corridors, a failed trunk render can mutate raw network termination/junction, so capture raw networks before rendering. After river diagnostics the generator initializes experienced temperature/vent visuals, assigns the base collider, reapplies the sediment override, and builds ocean/atmosphere visuals. Startup then completes environment and biology setup. [Ribbon emission](../Assets/Scripts/Planet/Geodesic/Hydrology/GeodesicRiverSystem.cs#L695) · [Crossings](../Assets/Scripts/Planet/Geodesic/Hydrology/GeodesicTinLakeCrossings.cs#L20) · [Collider and completion](../Assets/Scripts/Planet/Common/Generation/PlanetGenerator.cs#L997) · [Startup](../Assets/Scripts/Core/Startup/SimulationStartupController.cs#L719)

**Live reuse already works.** With the extracted threshold unchanged, `RebuildVisuals()` retains the TIN, raw networks, all-lakes routing, accepted corridors and delivery on the integrated path. It recomposes sediment and rebuilds lake surfaces, crossings and ribbons. `RefreshTinLakeVisuals()` alone only updates lake surfaces and classification. `SetRiverDestinationColours` updates the colour stream. If delivery is absent, the first toggle can replay parcel endpoints for observational analysis. [Visual rebuild](../Assets/Scripts/Planet/Geodesic/Hydrology/GeodesicRiverSystem.cs#L436) · [Destination colours](../Assets/Scripts/Planet/Geodesic/Hydrology/GeodesicRiverDestinationColours.cs#L24)

Mapping identity includes source/target geometry and mapping version. Hash realized inputs when an earlier step already computed them or when a mask/shoreline closes over multiple upstream controls.

`GeodesicGenerationFingerprint` is a diagnostic. With `logDrainageDelivery` active it emits a sorted, invariant manifest and SHA-256 hashes of heights, XYZ, indices, ocean masks and independent runoff. It reflects broad public fields, adds effective settings and seed domains, and includes Unity/platform/MVID and post-build values such as realized filter strength. A rebuild can change the MVID. Keep this diagnostic intact and give cache keys their own stable, explicit input contracts. Output hashes verify data integrity and equivalence. The independent-runoff hash covers local parcels, so verification also needs receivers, accumulated flow and lake/corridor edges. `PlanetGenerator.GenerationVersion` is 2 and startup config is version 22. Version stage mathematics and payloads independently and resolve migrated settings before lookup. [Fingerprint encoder](../Assets/Scripts/Planet/Geodesic/Hydrology/GeodesicGenerationFingerprint.cs) · [Manifest call site](../Assets/Scripts/Planet/Geodesic/Hydrology/GeodesicRiverSystem.cs#L172) · [Config migration](../Assets/Scripts/Core/Startup/SimulationStartupController.cs#L1199)

**Lookup before generation.** Persist each boundary under an input-derived key so a restart can check disk without sampling terrain, classifying oceans or running carving. Use the explicit effective settings allowlists above, canonical subdivision/build versions, and parent input keys. Effective values requiring terrain to exist, such as frozen membership, resolved sea level, selected height arrays and exact shoreline facets, belong in payloads or parent proofs. Derive the shoreline lookup identity from the ocean inputs, canonical ocean/render mapping identities and the masked-water and shoreline algorithm versions. Check realized mask/geometry digests when binding. Each child header also records the canonical output digests it consumed. On a partial miss, reuse a downstream record only after restored or regenerated parents match those digests. Same sizes, same subdivisions or the same seed alone are insufficient.

**Version policy.** Start with an explicit compatibility cohort for the validated native Windows/Unity runtime, including compatible Unity version, runtime/backend, architecture and numeric mode. Keep it independent of assembly MVID. Within that cohort, use separate semantic algorithm and binary schema versions for geology, topology/mapping, carving, TIN, lake routing, ocean connections and presentation. A generation-math change requires a bump at the affected stage and invalidates its descendants. Review the affected versions with every change to a generation dependency, including shared noise, shoreline and normalization helpers. Payload schema changes invalidate only the corresponding records and dependents. Old startup JSON is normalized through the current migration before keying.

Measure total time, disk and peak memory before enabling lossless compression. A format with compressed blocks must bound decoded lengths and check integrity on the decoded representation.

### Storage model and remaining uncertainty

- **Physical terrain.** Cell terrain is roughly 2–4 MiB plus components. Pre-carve XYZ and six render scalars take 5.63 MiB plus infill masks, scoped IDs and evidence. With the carved checkpoint, allow roughly **15–20 MiB** of fixed terrain data and common evidence at L6/L7.
- **TIN.** Store exact local area, drainage area, independent/accumulated runoff and receivers at `36T`, about **11.25 MiB**, plus exact input/visible/filtered height arrays as applicable (0.625 MiB per L7 float array). Use carved XYZ and mask by verified parent identity. Packed parcel endpoints with two ints and three doubles take **10 MiB** on disk. Keep the endpoint evidence needed for normal delivery diagnostics before the runtime releases it. A full fixed managed TIN is about **55.16 MiB**, including face, incident and flat-routing arrays. Start by rebuilding those derived query structures from exact inputs without accumulation or network extraction. A full query helper is about 26.87 MiB at L7.
- **All-lakes graph and ocean delivery.** The captured all-lakes geometry needs roughly **5.1 MiB** packed for 119,686 XYZ/carrier pairs and 136,524 indices (about 5.54 MiB with managed alignment). Ordered raw/adjusted samples, overlapping basin memberships and ancestry are variable. A million packed parcel IDs cost 3.81 MiB. Scope each ID to its TIN, lake or network table and preserve source enumeration order wherever it affects bytes or arithmetic. For corridors store ordered connection/target IDs, witnesses and sparse edits (8 B per index/elevation) plus delivery records. Avoid complete parcel trajectories and intermediate TIN copies.
- **Optional finished presentation.** Solid mesh buffers cost up to `48V + 4I` with XYZ, normals, UV and colour. That layout is 11.25 MiB at the base L7 dimensions before new sediment facets. Visible lake upload buffers at the reference threshold take about 1.41 MiB for XYZ, normals and indices. River buffers take `40V + 4I`, typically about 168 B per three-column longitudinal step, plus mouth/path/colour-span metadata. Keep destination colours as a generated stream. Final geometry has variable size because wet/dry splits and rim walls add facets.
- **Peak memory.** Decode into privately owned numeric buffers and transfer single-owner arrays where safe. Rebuild fresh mutable indexes, lazy debug views and required Unity data. Avoid keeping the encoded file, a decoded DTO, a deep clone and the active graph resident together. Membership materialization and simultaneous surface query helpers are larger risks than the disk read. L8 fixed render arrays are about four times larger. Decline entries that exceed bounded admission or restore capacity.


## 6. Persistent files and integrity

### Extend the existing cache infrastructure

[PlanetGenerationCache.cs](../Assets/Scripts/Planet/Common/Generation/PlanetGenerationCache.cs) resolves paths under `Application.persistentDataPath/SimulaVitPlanetCache`, hashes explicit keys to file names, opens binary payloads with magic/version markers, touches entries on successful use and prunes by age, count and bytes. The current writers open the final path with `FileMode.Create`. The readers construct arrays from encoded lengths before checking expected dimensions. The current content checks and write path need a stronger contract for a larger graph snapshot. [Path, hashing and prune helpers](../Assets/Scripts/Planet/Common/Generation/PlanetGenerationCache.cs#L441) · [Legacy reader](../Assets/Scripts/Planet/Common/Generation/PlanetGenerationCache.cs#L148) · [Legacy writer](../Assets/Scripts/Planet/Common/Generation/PlanetGenerationCache.cs#L208)

- Add a dedicated `SimulaVitPlanetCache/geodesic/v1` namespace. Parameterize or share SHA-256 naming, directory creation, best-effort touch and directory-scoped quota/clear logic. Keep existing legacy public methods, top-level files, key bytes, schema and quota intact. The legacy top-level prune/clear and the geodesic directory operate independently. Keep the static topology, unit render geometry and direction-mapping caches.
- Use one file per named boundary in `3, so a completed planet is a set of linked records. Choose the file name from the record kind and deterministic input digest. Store a fixed magic and schema, stage and algorithm stamps, compatibility cohort, input key, parent output digests, explicit count/length tables and a SHA-256 digest of canonical content. Use indexed numeric records and packed arrays. Rebuild references by scoped IDs. The full B restore requires a consistent chain of the records used by the active generation path, from Cell terrain through Ocean delivery. A missing or invalid suffix can be regenerated from the last validated boundary. Optional presentation files have separate keys and can be evicted independently.
- Write uniquely named temporary files in the same target directory. Complete the payload, compute its digest, flush and close, then publish with a same-directory atomic move or replace. Use immutable final files per key, letting a validated concurrent winner stand. Replace a proven corrupt file only while coordinating writers. If safe replacement is unavailable, leave generation successful and report a skipped write. Readers open committed names only. A crash can leave a valid subset of the staged records or ignored temp files. Parent proof checks prevent mismatched records from being bound together.
- Use a short cross-process lock for publish, eviction and clear, with a bounded wait and cache bypass on contention. Keep generation and ordinary reads outside the lock. Handle a file disappearing between lookup and open as a miss. Coordinate removal of invalid files with publication so a stale reader cannot delete a valid replacement. Remove abandoned temporary files once their writer is gone. Provide a separate **Clear Geodesic Planet Cache** action and an option to bypass cache for a reference run. Clear covers the geodesic namespace only. Clear removes currently committed files. The next successful publication can populate the cache again.
- Start with a proposed **1 GiB total and 64 committed records** for geodesic storage, **128 MiB per record**, and **256 MiB of decoded numeric data per attempted restore**, with a separate peak allocation budget verified for L6/L7. Reserve temporary-write space, cap aggregate staging and skip oversized records. Touch records after successful use. Prune obsolete versions and orphaned dependents first, then least recently used records, favouring presentation eviction when ages are comparable. Keep dependency misses cheap and regenerate evicted records as needed. Cache I/O, corruption or exhausted quota must still allow ordinary generation.

### Validate, restore and publish

1. **Preflight and decode.** After startup migration and normalization, resolve the concrete settings and expected stage keys. Open committed files by those keys. Verify header identity, compatibility, physical file length and expected topology dimensions. Validate every count, offset, index and multiplication before allocation against topology limits, the remaining file and the cumulative byte budget. Reject unsupported sections, invalid encodings, truncation, trailing bytes and digest mismatch. Check canonical parent output digests even if a parent was regenerated in this attempt.
2. **Validate numeric authority before binding.** Check finite values and ranges where the live contract requires them, preserving defined sentinels. Validate coordinates, barycentric samples, frozen and retained masks, component identities and shoreline witnesses. Validate basin hierarchy, scoped joins/outlet IDs, parcel membership and unique first-lake ownership. Check the directed lake/network/corridor delivery graph for cycles and validate independent runoff, destination buckets and conservation using current tolerances. Match corridor target and terrain edit witnesses to the source surface. Reconstruct only cheap indexes/facet queries and validate against restored arrays, with no fresh TIN accumulation or parcel trace required for a valid B hit.
3. **Bind static state in the current lifecycle order.** Restore Cell terrain and pre-carve/infill data early enough for layered ocean, resources and temperatures to see the same queries as a miss. Then install the exact carved surface and bind TIN, lake and delivery records to fresh owners. Capture raw networks before presentation can mutate termination/junction state. Keep authoritative delivery separate from mutable visual audit counters. A valid B hit rebuilds visible terrain, lake and river buffers with the existing code. An exact C hit uploads validated buffers and restores required path, outlet and audit metadata. Both create fresh meshes, GameObjects, renderers and collider bindings, and use the normal environmental and biological initialization path.
4. **Handle misses and stage publication.** Validate before live state is assigned where possible. On a cache-specific bind failure, tear down partial meshes, collider references and runtime fields, bypass the offending record and resume through the normal path from a clean boundary. Surface unrelated generation failures through the existing startup failure handling. Capture detached initial-generation values at their existing boundaries, including pre-carve geometry and evidence before it is overwritten or released. Publish only after the full generated planet and required checks succeed. For New Game, commit after successful startup initialization and before simulation resumes. For synchronous regeneration, commit after successful authoritative generation. A failed or cancelled attempt discards pending files. The cache contains initial terrain and hydrology values while ongoing chemistry, temperature, organisms, resource concentrations and runoff changes stay on the current planet.

For equivalent inputs, verification should compare exact bytes and relationship order as well as totals. The existing diagnostic fingerprint remains available. Do not use elapsed durations or the diagnostic manifest hash as equivalence criteria across recompilation. Verify per-stage output digests and preserve or reconstruct the evidence needed to emit the existing per-output hashes. Expose diagnostic-only evidence separately when it is expensive. Bypass only the affected cached stage when requested evidence cannot be supplied exactly.

Menu teardown restores collider and source mesh bindings and deactivates old river/lake roots before deferred destruction. Keep at most the active runtime copy plus bounded load/write staging. Recompute dynamic state each game and keep `UpdateRunoff` mutations detached from the persisted initial snapshot.
