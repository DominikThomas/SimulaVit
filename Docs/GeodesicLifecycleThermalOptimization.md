# Geodesic lifecycle thermal sampling pilot

P1 adds an optional prepared ocean vent lookup to the existing lifecycle temperature read on `codex/geodesic-performance`. Reference is the default. Source inspection and test preparation are complete. Runtime parity and performance acceptance are pending user results.

## Source path and cost

`Step` refreshes the coarse temperature generation and opens the per-agent cache for the step. Movement writes the packed world position, then due dissolved reactions and predation run before the reverse lifecycle pass. Passive radius easing can change position within the same cell and layer, and active movement can change all three inputs. Lifecycle reads the current packed `Position`, cell and layer. It needs neither a direction reconstruction nor a position at the cell or layer center. Reconstructing a local point from movement direction and radius would introduce a different floating-point path and could miss the position actually presented to lifecycle. [Step and lifecycle](../Assets/Scripts/Biology/Replicators/GeodesicBiologyRuntime.cs) · [Thermal cache](../Assets/Scripts/Biology/Replicators/GeodesicBiologyRuntime.Thermal.cs)

| Read | Reference behavior |
| --- | --- |
| Coarse background | Validate the active cell and layer and index `cell * MaximumLayerCount + layer`. A generation stamp makes the authoritative ocean read lazy per node. Layer 0 reads the surface field and deeper layers read the published ocean temperatures. The stamp advances when the completed ocean tick changes. |
| Candidate lookup | The experienced field checks initialization and cell range. For a nonempty range it resolves the resource grid and checks ocean habitat and layer again. The world-built angular-cap index includes a cell footprint pad and holds both submarine and terrestrial candidates in cell ranges. |
| Position cache | With candidates, the packed slot is reusable when the biology step, coarse generation, node and exact world position match. Earlier movement, reaction or predation reads can supply a hit. Without candidates, a finite world position returns the stamped background directly. |
| Vent evaluation on a miss | Convert world to planet-local with `InverseTransformPoint`. Walk the cell range, filter by habitat, take the outlet anchor magnitude, project onto the radial seafloor-to-bottom-center segment, and take the 3D distance. Evaluate the core and smootherstep falloff scaled by the square root of the outlet strength. Keep the strongest influence and blend against the configured source temperature. |

Repeated work includes the candidate and habitat checks on the read path and the anchor magnitude, strength calculation and outlet filtering on a vent-cache miss. The segment's top radius and candidate footprint already exist at world setup. A distant cell with an empty range skips the transform and distance work. A position outside a vent's actual support can still lie in a padded candidate cell and require distance checks. The user-run P0 captures estimate about 6.9 ms/step for A at 10,000 and 4.3 ms/step for D2 at 11,000 across the entire thermal read. Those sampled timings establish the priority of the read and leave the relative costs of candidate locality and cache misses open. [Reference vent lookup](../Assets/Scripts/Planet/Environment/Temperature/GeodesicExperiencedTemperatureField.cs) · [P0 measurements](GEODESIC_PERFORMANCE_ROADMAP.md#preliminary-user-run-p0-measurements)

## Prepared ocean lookup

Optimized setup builds an ocean-only candidate index from the authoritative cell ranges. It preserves submarine outlet order and copies the source normal, anchor magnitude, column top, core radius and bounded strength into a compact array. Each active layer in an ocean cell shares that cell's candidate range. This follows the existing habitat rule, with the individual sample's vertical distance controlling the actual reach. Lifecycle resolves this lookup once at entry and checks the range using indexed arrays. An empty submarine range can return the background even when the reference range contains terrestrial candidates. A miss in a nonempty range uses the cached `Transform` reference to call the same live `InverseTransformPoint`. [Prepared lookup](../Assets/Scripts/Planet/Environment/Temperature/GeodesicExperiencedTemperatureField.Lifecycle.cs)

All position-dependent arithmetic still uses the sampled point. The dot product, clamp, vector subtraction, magnitude, smootherstep and blend retain their operands and order. The shared influence function uses the same square root of clamped strength, computed at setup in Optimized. A finite nearest candidate with zero influence still takes the reference zero-influence blend. Both paths read the live falloff and source-fluid configuration when they evaluate a miss and use the same finite-position and coarse-temperature fallbacks. Bitwise equality is the expectation for matched inputs and a target of the prepared fixtures. [Vent model and reference](../Assets/Scripts/Planet/Environment/Temperature/GeodesicExperiencedTemperatureField.cs)

The prepared arrays belong to the experienced field and are released by its `Clear`. The lookup is usable with its original grid and an initialized resource field. World regeneration publishes a new candidate index and configures a fresh runtime, and geometry or support-radius edits follow the existing regeneration contract. Both samplers use the same per-slot cache. Its step and coarse generation checks expire entries, and cell, layer or world-position changes miss the key. The two candidate access paths share any valid value already obtained earlier in the step. The coarse cache keeps its existing publication boundary.

The reverse pass still reads temperature at the original call site after captured-prey removal and age advance for that slot. Each slot is read when visited. Swap-back moves the last packed organism after removal, and the loop continues to the next lower index. A newborn is thermally initialized at its separated position through the existing full sampler. The newborn enters beyond the remaining traversal range, even when a later removal moves it into a slot already visited. The cache can serve a moved organism only when the sampled inputs match. Birth and death ordering, stable identity, cap checks, RNG draws, reproduction and exposure policy, and carbon and energy transactions stay in the serial pass. Death recycling changes dissolved OrganicC and can record a saprotroph founder site. The normal death callback records statistics. Neither operation publishes a thermal field or changes the vent geometry within the pass. Normal founder paths and daughter temperature initialization keep their original sampling positions and times.

The pilot targets repeated work with a fixed world lifetime. An across-step result cache would also need exact transform, vent and background invalidation, and its reuse would depend on continuous motion and radius easing. Burst or Jobs would require input capture and a coordinate path verified against Unity transforms, plus any dispatch, completion and result costs. The managed lookup provides a smaller first comparison while keeping a single serial lifecycle.

## Measurement and memory

All per-organism work in either mode remains within the sampled `GeodesicBiology.Lifecycle.TemperatureAndVents` marker. The lookup selection at lifecycle entry is constant work and is visible in the inclusive lifecycle and simulation totals. Lookup construction runs once during optimized world setup, with elapsed milliseconds recorded as `lifecycle_thermal_lookup_setup_ms`. It scans the existing cell ranges at setup and retains three arrays with approximately `4 × (cells + 1) + 4 × ocean candidate entries + 28 × indexed outlets` bytes of payload, plus managed array and object headers. The cell offsets occupy about 160 KiB at subdivision 6. Building uses local counters and references with no additional staging arrays. Reference startup skips this allocation. There are no per-step buffers or per-organism allocations added by the pilot.

Expected savings come from direct range lookup, skipping terrestrial entries, and doing less work per submarine candidate on a miss. Transform and distance costs, exact cache validation and the coarse read remain. A workload with mostly cache hits or empty ranges has less candidate work to save. The prepared arrays add a startup cost and may change cache locality. End-to-end benefit and the size of the gain remain unmeasured.

The recorder appends seven columns after the P0 schema. The mode and setup cost are present in both profiling modes. Setup cost is repeated metadata for the world and is counted once. The other five columns are raw counts for detailed profiling's sampled slots. Basic rows report `n/a` for those counters. The P0 timings, column positions and stride are retained. [Performance recorder](../Assets/Scripts/Debugging/SimulationPerformanceAnalyzer.cs) · [P0 timing conventions](GEODESIC_PERFORMANCE_BENCHMARKS.md#reading-attribution)

| CSV column | Meaning |
| --- | --- |
| `lifecycle_thermal_sampling_mode` | Reference or Optimized for the Geodesic run. |
| `lifecycle_thermal_lookup_setup_ms` | One-time lookup build cost. Reference records zero. |
| `lifecycle_thermal_cache_hits_sampled` / `lifecycle_thermal_cache_misses_sampled` | Reads that reach the per-slot cache. Empty ranges bypass this cache. |
| `lifecycle_thermal_cache_key_invalidations_sampled` | Misses replacing a populated entry from the current biology step after a node, position or coarse epoch change. Step expiry contributes to misses. |
| `lifecycle_thermal_candidates_sampled` / `lifecycle_thermal_influence_evaluations_sampled` | Candidate entries visited on finite-input misses and entries checked for influence after habitat filtering. Influence checks include evaluations that return zero. |

`GeodesicBiology.Lifecycle.TemperatureAndVents_samples` already supplies the number of sampled calls. Calls can also exit on an invalid node or bypass the slot cache. Use the raw counts to compare sample mixes and the hit rate among cache lookups. Multiply by `detailed_slot_stride` for an estimated total when useful. Detailed timing includes collection for sampled calls, and basic profiling is the primary whole-step comparison.

## Correctness coverage

The prepared Edit Mode fixture compares bit patterns at the vent center, two positions in one node, around the core and support boundaries, on either side of a layer boundary, in a neighboring cell and far from influence. It repeats these comparisons after translating, rotating and non-uniformly scaling the planet. The runtime tests cover same-step cache hits, position and layer changes, coarse publication, vent-source changes, cleared vent data and nonfinite input. A lifecycle test exercises reproduction at a one-float eligibility boundary, daughter placement and initial thermal readiness, old-age removal, carbon recycling and reading the daughter after swap-back. The vent model fixture checks eligibility for all active layers, and the recorder fixture checks mode metadata and CSV alignment. ## Manual acceptance

1. Load the saved **A — 10,000 passive hydrogenotrophs** profile with automatic startup-config saving disabled. Keep its fixed seed and resolved gameplay settings. Use **New Game → Advanced → Performance recording → Lifecycle thermal sampling**. Start a fresh world on **Reference**, with recording and CSV on and detailed profiling off. Repeat from the same profile on **Optimized**, starting both from **Start Paused** and selecting requested **1×**. Use the same post-founder warmup, camera and observation settings. The selector is session-only and appears even when recording is off. [Protecting saved configurations](GEODESIC_PERFORMANCE_BENCHMARKS.md#keep-benchmark-settings-separate)
2. Compare post-founder windows at the same simulated ages and workload. Aim for at least three full recorder windows over about 60 real seconds per run, with three matched pairs. Keep the individual captures and repeat the matched pair with detailed profiling for thermal attribution. Match population, metabolism and locomotion shares, turnover, step duration and environment tick workload. Apply the same procedure to saved **A — 1,000 passive**, **D2 — 11,000 mixed** and **C — 1,000 predominantly active or fully flagellar** profiles. [Matched windows and repeat procedure](GEODESIC_PERFORMANCE_BENCHMARKS.md#capture-matrix-and-comparable-windows)
3. Record achieved simulated seconds per real second, `simulation_cpu_ms_per_step`, pure lifecycle CPU ms/step from `GeodesicBiology.LifecycleReproduction_avg_ms`, thermal ms/step from `GeodesicBiology.Lifecycle.TemperatureAndVents_estimated_avg_ms`, FPS, frame time including p95, and GC bytes per frame. Retain the population and metabolism/locomotion columns, lifecycle birth/death counts, sampled thermal work and actual mean step duration `sum(simulated_seconds) / sum(steps_executed)`. Keep active chemistry nodes and `chemistry_ticks`. Record transport tick deltas from the resource field's `CompletedTransportTicks` and thermal tick deltas from the surface field's `LastCompletedTemperatureTick` divided by the fixed thermal interval. Use the same environment cadence and comparable tick counts in each pair.
4. Convert frame-average CPU timing columns by summing `frames × avg_ms` and dividing by the total steps. Compute the steady-state thermal cost from the existing detailed marker. For the end-to-end comparison, add the one-time optimized lookup setup cost once over the measured step count and report both costs. Use the primary basic captures for whole-step CPU and compare runs against their repeatability. Use detailed captures to interpret cache behavior and candidate work. Avoid adding child markers to their inclusive parents.
5. Require at least **10% less end-to-end thermal sampling CPU ms/step at 10,000**, a whole-step CPU reduction above baseline variability, no meaningful regression at 1,000, and equivalent numerical and biological outcomes. Use the prepared fixtures and compare in-game position-dependent temperatures, reproduction readiness and exposure at matched vent and layer positions. Keep Reference as the default pending acceptance.
