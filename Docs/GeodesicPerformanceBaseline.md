# Geodesic performance baseline

The performance branch has a fixed-seed reference matrix and optional detailed attribution. The original recorder and historical validation are documented below. [Current P0 manual benchmarks](GEODESIC_PERFORMANCE_BENCHMARKS.md) · [Performance roadmap](GEODESIC_PERFORMANCE_ROADMAP.md)

This pass adds observation only. No chemistry, biological rules, movement, RNG, speed settings, or integration code has been changed. Saved startup settings and the confirmed Hydrogen to Fermentation mutation probability of **0.02** are preserved. No optimization or gameplay benchmark was performed as part of this pass.

## Current diagnostic defaults

In `PlanetScene`, opt in through **New Game → Advanced → Performance recording**. The startup controller configures the existing analyzer before enabling it. CSV writing and filename timestamps default to on. Periodic Console summaries default to off. The summary interval defaults to five real seconds. Unity Profiler markers remain available independently of the analyzer. [Startup controls and defaults](StartupSetupTabs.md#performance-recording) · [Runtime diagnostic inventory](GeodesicBiologyGrowthDiagnostics.md#runtime-diagnostic-inventory)

## Running a reproducible benchmark

1. Use Unity **6000.3.29f1**, matching [ProjectVersion.txt](../ProjectSettings/ProjectVersion.txt), with packages from [manifest.json](../Packages/manifest.json). Start from the same saved world/configuration and seed for every comparison; retain a copy of the existing configuration instead of resetting defaults. Record the exact Editor/package versions, Git revision and local diff, hardware, build target, resolution, camera position, population, geodesic subdivision/layers, thermal model, speed, rendering state, and enabled diagnostic observers. Keep pre-upgrade captures separate; collect a new baseline before comparing performance on the upgraded Editor.
2. Prefer a Development Build for performance comparisons. In the Editor keep the Game view size, Profiler connection, VSync/frame cap, focused window, and Inspector selections constant. Leave Deep Profile and allocation call stacks off during baseline collection. Main-thread elapsed time can contain waits and Editor overhead; it is not a GPU timing or hardware CPU utilization measurement.
3. Enable **Performance recording** in startup, keep CSV and timestamps on, and select a summary interval of **5** or **10** real seconds. Leave periodic Console summaries off for baseline comparisons. The Inspector's **Latest Summary** updates regardless of Console logging.
4. Let the world warm up for at least **30 real seconds** after initialization or restore. The capture begins as soon as the world is ready. Exclude warmup windows from performance comparisons.
5. Capture at least **60 real seconds** at one requested speed. Use separate captures for, for example, 1x, 10x and your usual high speed, restoring the same saved state before each run. Do not change settings, camera, selected organism, rendering, or speed inside a measurement window. Repeat each run three times. Compare windows from similar population and simulated ages because the population evolves while measured.
6. Return to the main menu or disable the analyzer to flush buffered CSV rows and the final partial window. The current unfinished frame is deliberately omitted. Use `simulated_seconds_per_real_second` and `steps_executed` to judge actual throughput under the authoritative step clamp. Resource chemistry has its own tick schedule, so also compare `chemistry_ticks`.
7. For observer overhead, repeat the same scenario with the analyzer disabled and compare Unity Profiler's frame measurements. This pass does not claim an experimentally established overhead budget. Do not use the existing legacy predator performance benchmark as a geodesic baseline: it constructs a different scenario and disables rendering.

## Measurement semantics

* Every completed rendered frame is observed. The old `recordEveryNFrames` decimation is replaced by configurable real-time windows; it no longer controls collection. Windows are consecutive, non-overlapping intervals, with an exact nearest-rank p95 across all captured frames in each window. A preallocated buffer holds 32,768 frames by default. Reaching its limit emits an explicitly flagged shorter window rather than silently dropping frames.
* The analyzer runs before simulation Update. It reads the last completed frame's profiler values and pairs them with metadata saved after the preceding frame's Updates. It discards the initial partial frame. Frame duration/FPS use successive monotonic real-time boundaries, not scaled/clamped simulation delta. CPU avg/p95 use Unity's main-thread frame marker; CPU and GC sample counts make unavailable engine data visible.
* All script recorders explicitly use `SumAllSamplesInFrame`, so repeated substeps, habitat samples and transport ticks contribute to a rendered-frame total. Completed marker samples are reset and explicitly restarted before the next simulation Update (Unity's Reset stops collection); a quiet frame cannot reuse an earlier tick's duration. Only the main thread is recorded for script markers. Legacy jobs' worker execution is not summed into main-thread wall cost; the existing synchronization markers remain detail columns.
* Actual steps are differences of `ReplicatorManager.SimulationStepCount`, not configured steps. Simulated advance is the authoritative clock difference, so an empty geodesic world can advance time with zero biology steps. Pauses, discarded deltas and clock regressions are not interpreted as configured work. Restore/restart a capture at world/clock changes to keep windows comparable.
* Total population, all eight metabolism counts, requested speed and active ocean chemistry nodes are **frame averages**. The metabolism averages use the same completed frames as `population_avg` and sum to it apart from floating-point roundoff. Use `end_simulated_seconds` as the x-axis for population charts. It records the absolute world clock of the last completed frame in each row. The existing `simulated_seconds` is the amount advanced during the window. Locomotion averages retain their existing per-simulation-step weighting.
* Chemistry candidates and processed nodes are **window totals of actual tick visits**, obtained from monotonic counters. Compare candidates/processed divided by `chemistry_ticks` to the average active node count. Frames with no chemistry tick add zero visits. Counters reset on world cleanup.
* Timing columns are milliseconds **per rendered frame**, including idle frames, not milliseconds per invocation. A registered inactive custom marker reads zero; an unavailable engine/legacy marker reads `n/a`. Non-development players without `ENABLE_PROFILER` disable the analyzer with one warning.
* Per-frame sampling uses preallocated arrays, value types and native recorder calls. Sorting, string formatting, Console output and CSV I/O occur at summary boundaries. `SimulationPerformanceAnalyzer.Sample` includes the observer's own collection and reporting cost in the following completed frame. The two new chemistry visit counters cost two integer additions per chemistry tick and do not influence simulation state.

### Scope accounting

| Summary aggregate | Definition |
| --- | --- |
| `simulation_total` | Existing `ReplicatorManager.Simulation` + resource Update + surface-temperature Update. These roots are disjoint. Includes their embedded diagnostics. In legacy mode this retains the replicator pipeline timing; it is not a new total for legacy resource-map execution. |
| `biology_reactions_including_competition` | Existing ReactionEvaluation parent; competition, commit, habitat and request markers remain inclusive detail columns. |
| `biology_lifecycle_and_founders` | Existing lifecycle/reproduction plus deferred/emergent founder scheduling. |
| `passive_movement_including_visual_targets` | Existing Movement minus ActiveMovement; includes passive scheduling, boundary traversal, vertical events and passive visual target writes. |
| `active_movement_including_sensing` | Existing ActiveMovement parent; sensing remains a detail, already included in this number. |
| `abiotic_chemistry` | New whole-Step parent surrounding the existing chemistry/scan/visual-memory markers. Includes setup and visual-memory decay. |
| `ocean_transport_and_environment` | Resource + surface-temperature Update minus whole chemistry and their separately marked diagnostics. Includes vents, air-sea exchange, dissolved and particulate transport, and synchronous thermal callbacks. |
| `rendering_visual_sync` | Existing VisualSync + ocean Fe2/sediment visual Updates + vent LateUpdate. ReplicatorRenderSystem is an inclusive detail, not added again. Covers instrumented CPU synchronization/submission, not the full engine render pipeline/GPU. |
| `telemetry_debugging` | Explicit biology/resource/thermal diagnostics, manager movement diagnostics, frame telemetry, chemistry telemetry, HUD and analyzer scopes. Diagnostic operations fused into per-agent biology/render loops remain attributed to those parent systems. |
| `measured_total` | Simulation roots + rendering roots + telemetry outside those roots. Embedded telemetry is not added a second time. This is instrumented application work, not the entire CPU frame. |

**Do not sum every column.** Simulation/measurement totals are inclusive; several detail markers and the telemetry view overlap those totals. Unclassified biology setup/control synchronization remains in the simulation root; it is not artificially assigned to a biological reaction. Existing legacy steering/metabolism/state synchronization/JobHandle columns are retained as details. No existing marker names were renamed.

Unity's frame-sum option is documented in [ProfilerRecorderOptions](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Unity.Profiling.ProfilerRecorderOptions.html).

## Prioritized suspects from source review

These are priorities for measurement, **not a measured ranking**.

1. **Population-wide passes at every requested biology substep.** `ReplicatorSimulationPipeline.RunFrame` loops over requested steps (`Assets/Scripts/Core/Simulation/ReplicatorSimulationPipeline.cs:236`). `GeodesicBiologyRuntime.Step` calls movement and lifecycle every step (`Assets/Scripts/Biology/Replicators/GeodesicBiologyRuntime.cs:475`). Movement scans population separately for active-time accumulation, passive wander, passive kinematics, active movement, passive vertical events and visual targets (`.../GeodesicBiologyRuntime.cs:1056`; `.../GeodesicBiologyRuntime.Locomotion.cs:184`). Several scans occur even when the kinematics interval has not elapsed, or the relevant locomotion population is empty. Lifecycle scans all agents for age, maintenance, thermal exposure, colors, division and diagnostics (`.../GeodesicBiologyRuntime.cs:764`). **Hypothesis:** at high speed these passes dominate even while reactions and kinematics have interval gates. Compare movement detail, lifecycle and reaction averages before considering pass fusion or locomotion index lists. Skipping lifecycle work would change semantics and is not recommended.
2. **Diagnostic scans and reports can accelerate with simulated time.** Biology's report gate is ten simulated seconds (`.../GeodesicBiologyRuntime.cs:500,533,1484`). Its report invokes multiple diagnostics and scans population; sulfur reporting allocates an `int[8]` (`.../GeodesicBiologyRuntime.Sulfur.cs:105`). Movement diagnostics, when enabled, maintain dictionary observations and scan passive agents every substep (`.../ReplicatorMovementDiagnostics.cs:96`). Resource recurring diagnostics recompute seven active-node summaries and layer means (`Assets/Scripts/Planet/Environment/ResourceSimulation/GeodesicOceanResourceField.cs:655,869,996`). Chemistry telemetry also scans columns/nodes, but already has a real-time minimum gate (`.../GeodesicChemistryTelemetry.cs:69,81`); do not assume that gate is absent. **Hypothesis:** telemetry creates spikes and GC at high multiplier. Use telemetry scopes and compare with diagnostic observers off, preserving simulation parameters. Cached O2 means may have simulation consumers; do not simply throttle them with display-only statistics.
3. **Transport remains topology-wide despite sparse chemistry.** Every resource tick clears a seven-channel capacity-sized staging buffer, traverses enabled horizontal channels and all vertical links, then applies seven channels to every active node while refreshing chemistry candidates (`.../GeodesicOceanResourceField.cs:637,673,718,744`). Chemistry itself visits only candidates (`.../GeodesicAbioticChemistry.cs:131`), while visual memory still scans all columns (`.../GeodesicAbioticChemistry.cs:120`). Particulate transport makes two full link passes per species that has ever produced material, and scans active nodes/cells (`.../GeodesicOceanResourceField.cs:824`; `.../GeodesicOceanSuspendedField.cs:71`). **Hypothesis:** sparse reactants will not imply cheap transport. Compare candidate counts, CandidateRefresh, Transport, horizontal/vertical and chemistry timings. Uniform dissolved horizontal channels are already skipped; preserve that existing optimization.
4. **Thermal/habitat queries and active sensing.** Reaction evaluation has separate habitat/request/demand/availability/commit passes (`.../GeodesicBiologyRuntime.cs:516,603,613,644,677`). Habitat caching is sparse by occupied node, and coarse temperatures already use epochs (`.../GeodesicBiologyRuntime.cs:1330,1365`). Organism-position thermal caching resets per biology step and validates local vent candidates (`.../GeodesicBiologyRuntime.Thermal.cs:14,29`). Active sensing has its own countdown and cached node observations (`.../GeodesicBiologyRuntime.Locomotion.cs:80,376`). **Hypothesis:** local temperature/suitability computation is expensive in vent populations. Measure HabitatSampling, RequestBuild and ActiveMovement.Sensing; do not replace organism-position temperature with coarse cell temperature.
5. **Control conversion and a likely per-step delegate allocation.** `ReplicatorManager.RunGeodesicBiologyStep` reapplies controls and builds steering/temperature value structs each step (`Assets/Scripts/Biology/Replicators/ReplicatorManager.cs:1055,1077`). The `RegisterDeathCause` instance method group is passed as an Action on every call (`.../ReplicatorManager.cs:1089`). **Hypothesis to confirm in GC allocation samples/compiled IL:** the instance delegate is allocated per substep. Struct construction itself is not evidence of heap allocation. The new GeodesicControlSync detail isolates control application. This is the recommended first small optimization: cache that instance delegate once, then verify parity and the allocation reduction. No RNG, cadence or integration changes are needed.
6. **Rendering, companion state and growth allocations.** `ReplicatorRenderSystem.RenderAgents` scans the packed population once per rendered frame, updates growth presentation and submits mesh batches (`.../ReplicatorRenderSystem.cs:35`). Growth of presentation lists, packed-state buffers, thermal caches and new daughter objects can allocate (`.../GeodesicBiologyRuntime.cs:834`; `.../GeodesicBiologyRuntime.Thermal.cs:36`). **Hypothesis:** these explain population-dependent visual cost or episodic GC; profile VisualSync/RenderAgents and GC alongside births. `EnsureMatchesAgentCount` has a count-equality fast path (`.../ReplicatorPopulationState.cs:83`); there is no evidence that geodesic stepping performs the legacy full companion synchronization on every step. Do not optimize a synchronization pass that is not on this path.

A larger follow-up candidate, after measurement, is reducing **display-only** diagnostic work with real-time throttling and reusable report buffers. That must preserve accounting windows, simulation-consumed caches and biological observations. Population pass fusion and sparse particulate tracking are later changes requiring much stronger parity checks. They have not been implemented here.

## Historical validation (Unity 6000.3.19f1)

The results below are the original record, not validation on Unity **6000.3.29f1**. They were not repeated by this documentation maintenance pass.

Native validation used a disposable project under `Temp/PerformanceBaseline/UnityValidation`, with a separate company identity and a startup-config save guard only in that disposable copy. The working project's scene/configuration was not rewritten for the test run. Unity licensing required execution outside the restricted sandbox; no license or project settings were changed.

* Production and EditMode test assemblies compiled successfully using the installed Unity compiler and restored compiler response files. `Tools/ValidateHydrogenotrophy.ps1 -CompileManaged`: **55 selected existing managed checks passed** (`Temp/PerformanceBaseline/compile.log`).
* Unity EditMode: **179 passed, 3 failed out of 182** across performance-summary arithmetic, speed semantics, biology runtime, abiotic chemistry, horizontal mixing, manager lifecycle, locomotion mutation, fermentation and sulfur runtime fixtures. All three new summary tests passed. Results: `Temp/PerformanceBaseline/EditMode-results.xml`; log: `Temp/PerformanceBaseline/EditMode-native.log`.
* Unity PlayMode: **4/4 passed**. Checks cover seven marker invocations in one frame, zero/stale handling on an idle frame, the actual analyzer continuing to collect after frame resets, enable/disable preserving Unity random state/time settings, and a partial-window CSV flush with matching columns and invariant numbers under a decimal-comma locale. Results: `Temp/PerformanceBaseline/PlayMode-results.xml`; log: `Temp/PerformanceBaseline/PlayMode-native.log`. The uniquely named test CSV was removed afterward.
* The three EditMode failures were rerun with all modified production scripts replaced by their **uninstrumented HEAD versions only inside the disposable copy**. All three reproduced with identical assertions (`Temp/PerformanceBaseline/baseline-regressions-results.xml`):
  * `GeodesicBiologyRuntimeTests.FixedPassiveTickPreservesDisplacementWithinDocumentedTolerance`: expected approximately 0.011459 degrees; float angle readout is zero.
  * `GeodesicBiologyRuntimeTests.VerticalScheduleIsDeterministicAndFinite`: test expects 0.015 opportunities/s; current source is 0.0015.
  * `ReplicatorManagerLifecycleTests.WorldClock_RemainsRunnableAcrossRepeatedBiologyDeinitialization`: the fixture's manager has no pipeline in EditMode. Its later expectation of one executed step for an uninitialized runtime also predates the current zero-step semantics.

Those existing tests/behaviors were left unchanged. Final sources were restored to the disposable copy before the successful final PlayMode run. This validates the observer mechanics and selected existing invariants; it does not establish a runtime bottleneck ranking, an observer overhead budget, or full-world biological parity across arbitrary experiments. Those require the reproducible measurements described above.
